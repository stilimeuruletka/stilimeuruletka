## Симптом
- Пользователь появляется в `users`, но таблица `referrals` остаётся пустой (нет друга, нет +1 спина).

## Ожидание
- При заходе нового пользователя по `startapp=ref_<код>` должна создаваться запись в `referrals` и начисляться +1 спин пригласившему.

## Гипотезы
- H1: Пользователь сначала открыл `blog_*` (или приложение без ref), поэтому в момент `ref_*` он уже не новый → `handle_start` не создаёт referral.
- H2: `start_param` не доходит до `/api/me` (пустой/невалидный), поэтому `handle_start` вызывается без корректного `p_ref_code`.
- H3: `p_ref_code` приходит с префиксом `ref_` и не режется (сравнение с `users.referral_code` не находит пригласившего).
- H4: В БД нет пригласившего с таким `referral_code` (например, код не тот/скопирован не полностью).
- H5: Вызов `/api/referrals` не отражает данные из-за ошибки RPC/авторизации (таблица не пустая, но API возвращает пусто).

## План сбора доказательств
- Сымитировать 2 сценария (новый юзер с `ref_*` и юзер, который сначала открыл `blog_*`, а потом `ref_*`) и сравнить, появляется ли запись в `referrals`.
